# weekly-ops-review

Review the week's operational performance and identify what needs attention. Cocorita's primary operating rhythm.

## When

- Weekly, ideally Monday after service (the main revenue day) or Tuesday morning.
- Whenever André surfaces operational signals that warrant a structured pass — score drop, team friction, demand spike or dip.

## How

1. Pull current state from `state.md`. Note last review date if logged in `sessions.md`.
2. Ask André for: order counts by day (Sex / Sáb / Seg), operational incidents, team issues, customer complaints, score movement.
3. Compare counts to capacity benchmarks: Sex 4–12, Sáb 18–24, Seg 36–60. Flag below-trend or above-trend (above-trend without prep is also a risk).
4. Walk the kata triad — limpeza, organização, método — and ask what slipped this week.
5. Triage: which gaps are root cause (operational) vs symptom (perception)?
6. Identify ONE operational improvement to implement in the coming week. Just one. Multi-fix weeks fail.
7. If a financial implication surfaces (compensation, supply cost, partner question), frame the operational case and flag for Ben.
8. Append to `sessions.md`: order counts, key incidents, the one chosen improvement, owner.

## Bounds

- One improvement per cycle. No omnibus action plans.
- Don't propose anything that requires André to be physically present. If a fix only works with André on-site, the fix is wrong.
- Don't propose operational changes that require the financial picture before they're worth running. Those go to Ben first.
